# PPT基本演绎法

把 PPT 学习内容"演绎"成一篇自包含的理解型 Markdown 笔记。核心立场：**笔记是对知识的重新表达，不是对幻灯片的逐页转录。**

## 铁律（不可违反）

1. **零元数据**：笔记中禁止出现页码、文件名、"第 X 页"、"幻灯片"、"PPT 显示"、"如图 X 所示"等一切出处标记。笔记读起来必须像作者独立写成的文章。
2. **零图片引用**：禁止用 `![](...)`、截图、文件链接代替任何图。所有框架图、流程图、拓扑图、逻辑图、对比图必须用 Markdown 原生方式还原：Mermaid、表格、ASCII 图、结构化文字（选择规则见下文）。
3. **可讲解性**：写完后自检——一个没看过原 PPT 的第三方（人或 AI），仅凭这篇笔记能否完整、准确地向他人讲清全部要点与逻辑？不能则继续补写，直到能为止。
4. **不丢信息**：重构可以重排顺序、合并拆分、换表达方式，但不允许丢弃实质性论点、数据、定义、因果链。舍去的只能是重复与修辞性内容。

## 工作流程

### 第一步：完整摄取（先读全，再动笔）

- 用可用工具提取 PPT 全部内容：文本逐页提取（如 python-pptx / pdfplumber），**每页的图片、图表、SmartArt 必须逐一用视觉能力实际查看**，不能只看提取出的文字。PPT 的信息常常一半在图里。
- 记录两类素材：
  - **显性内容**：标题、正文、数据、定义、引用。
  - **隐性结构**：页面之间的承启关系、反复强调的概念（通常是核心）、图与文互相补充的部分、演讲者的论证路线（问题→分析→方案，或现象→原理→应用等）。
- 同时留意**作者痕迹**：原作者的叙事顺序、详略分配、刻意渲染与一笔带过的内容、流露出的立场与受众假设。先记下来——第三步重构会主动抛弃原结构，而第六步的批判性审视恰恰需要这些原始证据。

### 第二步：解构（拆掉原结构）

把素材摊平成"知识原子"清单：每条是一个独立的事实、概念、判断或关系，不保留任何页序。然后回答三个问题：

1. 这份材料**真正想让人记住的核心结论**是什么？（通常 1–3 条）
2. 支撑这些结论的**论证骨架**是什么？（前提 → 推理 → 结论；或问题 → 根因 → 对策）
3. 哪些是**细节与例证**？（服务于骨架，可分层收纳）

### 第三步：重构（按理解重新组织）

忘掉原 PPT 的章节顺序，按"最利于理解"的逻辑重排：

- 先结论后展开，或先问题后解答——取决于哪种更符合认知顺序。
- 概念按依赖关系排序：先定义再推理，先整体再局部。
- 原 PPT 为演讲效果做的铺垫、悬念、重复，一律改为直给的书面逻辑。

### 第四步：演绎成稿（费曼式写作）

写作时持续套用费曼学习法：

- **通俗化**：每个专业概念都配一句"说人话"的解释或类比，再给出准确定义。术语第一次出现时就地解释。
- **讲清"为什么"**：不只写"是什么"，凡有因果、动机、设计取舍处必须写出理由。这是"可讲解性"的主要来源。
- **暴露盲区**：写作中发现自己讲不清楚的地方（逻辑断点、含义模糊的术语、图里看不懂的部分），重新回读原材料弄懂后再写；原材料确实未覆盖的，在笔记中明确标注"原文未展开"，不得编造。

### 第五步：渐进式总结（分层结构）

成稿采用由略到详的分层结构，读者可停在任意一层：

1. **一句话总览**：整份材料的核心，一句话说清。
2. **要点速览**：3–7 条核心要点，每条一两句。
3. **分层展开**：正文各章节，完整论证 + 还原的图表 + 关键数据。
4. **（可选）细节附录**：术语表、数据明细等，供查证。

章节标题用"断言式"（写出该节结论，如"缓存不一致的根源是写穿透缺失"），不用"标签式"（如"3.2 缓存问题"）。

### 第六步：还原作者的构思，并批判性审视（笔记收尾章节）

笔记正文之后，必须追加最后一章《作者的构思与不足》，供学习者跳出内容本身、审视这份材料的"设计"。依据第一步记下的作者痕迹回答两组问题：

**A. 作者为什么这样写这份材料？**

- **目标与受众**：作者想让谁看完记住什么、做什么？（教学、汇报、说服、销售、立项？）
- **叙事策略**：为什么选择这个顺序和详略？开头的钩子、中间的铺垫、收尾的落点各自服务于什么效果？
- **取舍逻辑**：哪些内容被放在了核心位置、哪些被压缩或省略？这种分配暴露了作者认为什么重要、什么不重要。

**B. 这个构思的不足是什么？** 逐类排查，每类有则写、无则略：

- **客观限制**：篇幅/时长/受众背景/场合等约束导致的妥协（如为控制时长而跳过推导）。
- **认知盲区**：作者单纯没想到的——缺失的视角、未覆盖的反例、过时的前提、未回答的显然问题。
- **有意隐藏**：刻意淡化或回避的东西——不利数据、替代方案、利益相关、未声明的假设、营销话术包装下的立场。判断依据：论证在某处突然含糊、对比缺少对等项、只给结论不给证据、情绪词替代数据。

写作要求：

- 每条判断必须给出**依据**（从原材料的哪个具体特征推断）；纯推测的部分明确标注"推测"，不得把猜测写成事实。
- 对事不对人：分析的是材料的设计，不是攻击作者；不足之处同时尽量给出"如果补全会是什么样"。
- 本章是元评论，允许提及"原作/原材料/作者"，但仍不得出现页码、文件名等具体出处标记。

## 图表还原选择规则

| 原图类型 | 首选还原方式 |
|---|---|
| 流程、步骤、决策分支 | Mermaid `flowchart` |
| 时序、交互、调用过程 | Mermaid `sequenceDiagram` |
| 层级、组织架构、分类树 | Mermaid `flowchart`（自上而下）或缩进列表 |
| 系统架构、模块关系、拓扑 | Mermaid `flowchart` + `subgraph` 分层 |
| 状态流转 | Mermaid `stateDiagram-v2` |
| 时间线、阶段演进 | Mermaid `timeline` 或 ASCII 横向时间轴 |
| 对比、多维属性 | Markdown 表格 |
| 比例、组成 | 表格（含占比列）或结构化文字 |
| 简单空间布局、示意 | ASCII 图（等宽代码块） |
| 复杂且上图均不足以表达 | 结构化文字分点描述（要素 → 关系 → 走向） |

还原图的要求：

- **信息保真**：原图中的节点、连线、方向、标注文字一个不少；颜色/位置等纯视觉信息可舍。
- 图前后用一两句话说明该图表达的关系与读法（费曼原则：确保读者看图前就懂它在说什么）。
- 不确定 Mermaid 能否渲染时，退而求其次用 ASCII 图，保证任何 Markdown 阅读器都可见。

## 输出前自检清单（逐项通过才可交付）

- [ ] 全文搜不到：页码、文件名、"幻灯片"、"PPT"、"第 X 页"、"如图"等出处标记
- [ ] 全文搜不到 `![`（无任何图片引用）
- [ ] 原 PPT 每张含信息的图都已用原生方式还原，无遗漏
- [ ] 开头有一句话总览 + 要点速览
- [ ] 每个术语首次出现处有通俗解释
- [ ] 每条因果/结论都写了"为什么"
- [ ] 章节标题是断言式
- [ ] 模拟第三方通读一遍：逻辑无断点、无"这里要看过原片才懂"的暗坑
- [ ] 原有实质性论点、数据、定义与原材料逐条核对，无丢失
- [ ] 末尾含《作者的构思与不足》章节：构思分析（目标受众/叙事策略/取舍逻辑）+ 不足排查（客观限制/认知盲区/有意隐藏）
- [ ] 批判章节的每条判断均有原材料依据，推测部分明确标注"推测"

## 交付

- 输出单个 `.md` 文件，保存到当前工作目录，报告绝对路径。文件结构：一句话总览 → 要点速览 → 分层展开正文 → （可选附录）→ 《作者的构思与不足》收尾。
- 篇幅不设下限，以"完整可讲解"为准；但同一信息不重复出现两遍。
- 输出模板与一份完整范例见 [references/output-template.md](references/output-template.md)，写作前阅读。
